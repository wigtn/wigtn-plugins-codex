# v0.5.5 — WorkGraph 선택 조회

저장된 계획에서 특정 작업을 재개할 때 전체 작업 기록을 읽던 경로에 `inspect --task TASK-ID`를 추가했습니다. 예를 들어 두 작업을 확인할 때 `--task`를 두 번 지정하면 해당 작업과 전이적 선행 작업, 연결된 검사·산출물·요구사항·소스를 반환합니다. 옵션을 생략하면 기존 전체 조회를 유지합니다.

전체 그래프 검증·소스 변경 감지·요약·릴리스 게이트는 선택 밖도 계속 검사합니다. 생략 개수와 조회 범위를 명시하며, 알 수 없는 작업 ID는 오류로 처리합니다. `saved_revision`으로 저장된 revision과 변경 감지 후 임시 revision을 구분합니다. 조회는 파일을 변경하거나 저장된 검사 명령을 실행하지 않습니다.

Work Planner 스킬에는 작업 ID를 알 때 사용할 선택 조회 예제를 직접 제시했습니다. 수정용 참조 문서는 상태 수정이나 추가 의미 설명이 필요한 경우 읽도록 바꿨습니다. Knowledge Wiki는 공동 버전 정책에 따라 manifest만 0.5.5로 올렸습니다.

## 실측 결과와 범위

[테크리포트와 원본 증거](scoped-inspect-2026-09-08/report.ko.md)를 함께 공개합니다. 후속 비교는 GPT-6 Astra medium에서 내부 합성 상태 조회 8개 사례를 조건당 한 번씩, 총 16회 실행한 결과입니다.

| 지표 · 조건당 8회 합계 | v0.5.4 | 최종 후보 |
|---|---:|---:|
| 요구 항목 정답 | 8/8 | 8/8 |
| 총입력 토큰 · 캐시 포함 | 696,334 | 304,669 |
| 총입력−캐시 입력 · 단순 차감 | 113,934 | 82,589 |
| 경과 시간(초) | 302.739 | 190.268 |

총입력 합계는 56.2% 감소했습니다. 비용, 일반 코딩 품질, 실제 제품 개발 성능의 개선율을 뜻하지 않습니다. 경과 시간에는 서버 상태와 캐시 영향이 남습니다. 개발자와 평가 설계자가 같으며 외부 독립 평가가 아닙니다.

앞선 1차 24회는 다른 후보와 사례를 사용했으므로 후속 16회와 합산하지 않습니다. 입력이 증가한 1차 실행과 전체 연결 그래프에서 도구 응답이 커진 경계 사례도 보존했습니다.

## 릴리스 검증

- `./scripts/validate.sh`: 전체 저장소·플러그인·스킬·정적 계약 검증 통과. 선택 조회 회귀 테스트 14개 포함.
- 추가 경계 검사 6개 재실행 통과: 손상된 설정/증거, 선택 밖 손상 작업, 선택 안팎 소스 누락, 공유 검사 연결.
- 보관된 1차·후속 세션을 복사본에서 재채점해 결과 JSON이 기존과 정확히 일치함을 확인.
- 원본 archive manifest의 2,594개 + 1,939개 파일 해시 검증 통과. 인증 폴더·파일·심볼릭 링크는 증거 묶음에 포함하지 않음.
- Core 플러그인의 manifest 버전 필드 외 모든 파일이 실측한 후속 후보와 일치함을 확인. 보관된 스냅샷은 수정하지 않음.
- 현재 재현 스크립트는 스냅샷 manifest에서 설치 버전을 읽도록 수정. `prepare --suite followup`으로 v0.5.4/v0.5.5 스냅샷과 기존과 동일한 과제·실행 순서를 생성함을 확인. 릴리스 준비 중 추가 모델 호출은 하지 않음.

실험 시점의 후보 manifest는 0.5.4였습니다. 릴리스 버전만 0.5.5로 변경했으며, 재현 스크립트의 버전 경로 수정과 문서 편집을 모델 성능 재측정으로 취급하지 않습니다.
