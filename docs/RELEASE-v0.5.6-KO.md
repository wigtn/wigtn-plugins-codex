# v0.5.6 — 요구사항 원문 보존과 단일 문서 범위 수정

요구사항을 가져오는 과정에서 본문이 손상되던 문제와, 단일 화면 명세·개발 인계에
전체 묶음 검증을 적용하던 문제를 수정했습니다.

## 요구사항 원문 보존

기존 importer는 본문의 밑줄·별표·backtick을 제거하고 공백을 합쳤습니다.
예를 들어 `unit_price * quantity`가 `unitprice quantity`로 바뀔 수 있었습니다.
이 정규화를 이전 근거의 재사용 판단에도 적용해 서로 다른 요구사항을 같은 것으로
취급할 수 있었습니다.

이제 본문의 식별자·연산자·기호·내부 공백을 보존합니다. 목록·표 입력, 음수,
공백을 포함한 리터럴, 본문 변경 시 검증 무효화와 동일 본문의 검증 재사용에 대한
회귀 검사를 추가했습니다. 기존 형식별 import와 재개 검사는 유지합니다.

이미 저장된 원문이 손상됐다면 소스를 다시 import하고 검증해야 합니다.
저장된 WorkGraph를 자동으로 다시 쓰지는 않습니다. 원문 보존으로 명시 ID가 없는
형식의 자동 생성 ID가 바뀌거나, 서식 변경만으로도 이전 근거가 무효화될 수 있습니다.

## 요청한 문서만 작성·검토

screen-spec은 사용자가 요청한 산출물·경로·형식을 따릅니다. 기존 문서는 입력으로
참조하고 템플릿은 필요할 때 사용합니다. 단일 채팅 답변이나 사용자 지정 Markdown은
관련 요구사항을 직접 검토하며, 묶음 검증기를 통과시키려고 다른 문서를 추가하지 않습니다.

번호가 붙은 WIGTN 산출물 묶음과 의존 문서가 요청 범위에 있는 경우에는 기존
묶음 검증기를 사용합니다. 이 검증기의 구조 검사와 회귀 테스트는 유지합니다.

## 호환성과 검증 범위

- 기존 Core 9개 스킬과 명시 호출형 `verified-delivery`를 유지합니다.
  실험 브랜치의 스킬 삭제는 포함하지 않습니다.
- Knowledge Wiki는 공동 버전 정책에 따라 manifest 버전만 올립니다.
- `bash scripts/validate.sh`의 저장소·플러그인·스킬·정적 회귀 검사가 통과했습니다.
  기존 importer에서 버그를 재현했고 실제 WorkGraph CLI의 원문 보존도 확인했습니다.
  릴리스 검사 로그는 [release-v0.5.6-validation.log](release-v0.5.6-validation.log)에 보존합니다.
- 수정본의 추가 모델 벤치마크는 수행하지 않았습니다. GPT-6 속도·토큰·코딩 품질
  향상을 주장하는 릴리스가 아닙니다.
