# Visual Craft

Make the requested interface or document feel specific to its content and audience.
Preserve the user's format, language, factual meaning and existing design system.
This is a craft layer, not a prerequisite planning pipeline.

## Apply only what the artifact needs

- Use the brief, real content and representative existing work to choose hierarchy
  and density. If these already settle the direction, proceed without a style menu.
- For frontend implementation or visual refinement, read [UI](references/ui.md).
  For authored documents, reports, slides or substantial prose, read
  [documents](references/documents.md). Read both only for a document with a custom
  web interface. Do not turn a plain document into a website or slide deck.
- Available document, PDF and presentation skills own file creation and rendering;
  product-spec and screen-spec own their requested content contracts. Apply craft
  within those workflows, without repeating their planning or verification.
  An existing design-direction decision is input, not a reason to restart design.
- Use this independently when those skills are absent. Change only the requested
  artifact; a local adjustment does not authorize a site-wide redesign.

## Shared decisions

- Give each section a clear purpose. Separate unrelated decisions; combine repeated
  explanations. Dense tables and reference material may need high information
  density. Do not delete requirements or evidence to make a layout airy.
- Establish hierarchy through grouping, type and spacing before adding containers.
  Repeated cards, nested panels and tiny labels should earn their place.
- Choose alignment for the reading order and content relationships. Neither left
  alignment, centering nor asymmetry is a universal style requirement.
- Avoid decorative status dots, numbering, symbol strips and em-dash slogans in
  newly authored copy. Preserve meaningful punctuation, genuine state indicators,
  ordered steps, source quotations and brand marks, including the WIGTN logo dot.
  An explicit user style or established brand takes precedence over these defaults.
- Let sentences wrap naturally. Do not force line breaks or isolate one italic or
  colored word merely to make a heading look designed. A deliberate title treatment
  is valid when requested and checked at the actual output sizes.
- Write concrete copy in the audience's language. Keep familiar technical terms
  when they are clearer than a forced translation. Do not invent metrics, customer
  quotes, awards, screenshots or product capabilities as decoration.
- Do not replace a generic look with another preset. Fonts, palettes, radii and
  motion are choices tied to this artifact, not global bans or mandatory effects.

## Finish proportionately

For a created or substantially edited artifact, follow the
[automatic checks](references/automatic-checks.md): scan explicit HTML/Markdown
files and inspect rendered geometry when an authorized browser is available.
Treat contextual findings as review prompts, not mandatory style changes.
Inspect the rendered artifact using the relevant reference and available tools.
Fix observed reading, overflow, hierarchy and interaction defects together, then
recheck affected views. Stop when the requested output works; do not add a style
score, redesign rounds or new deliverables unless requested. Distinguish rendered
checks from source-only review and report material unchecked areas honestly.
