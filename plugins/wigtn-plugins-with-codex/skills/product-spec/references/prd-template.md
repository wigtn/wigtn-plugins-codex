# PRD Template

Use only the sections that improve the implementation contract.

```markdown
# <Feature> PRD

## Context and problem
## Goals
## Non-goals
## Users and key scenarios
## Functional requirements
| ID | Requirement | Priority |
## UX, roles, routes, and states
## Non-functional requirements
## Acceptance criteria
| ID | Observable criterion | Verification method |
## Assumptions and open decisions
## Risks and mitigations
## Delivery outline
```

Requirements describe necessary behavior, not a preferred implementation unless the constraint is real. Use durable IDs such as `FR-101`; never renumber an existing PRD merely to make the document prettier.
